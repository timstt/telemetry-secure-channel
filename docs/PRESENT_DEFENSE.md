# Захист демонстраційної програми Telemetry.Present

Цей файл — підготовка команди. Підказки для виступу не показуються на сторінці викладача.

## Що сказати за 2 хвилини

> Для захисту ми зробили локальну сторінку, яка показує шлях кадру через усю систему: прогноз, стиснення, пакування, передавання й перевірку на приймачі. Вона запускається однією командою, працює через `HttpListener` на localhost і не потребує зовнішніх бібліотек чи інтернету.
>
> Дані блоків беруться з наших алгоритмів, еталонних пакетів і збережених результатів експериментів. Наприклад, для `ref_04` кодер відтворює бітовий потік еталона: 6144 біти сирих кадрів, 3389 біт потоку Гаффмана, 5568 біт навантаження і 6168 біт усього пакета. Маленькі приклади дерева й рюкзака на сторінці явно позначені як навчальні.
>
> Кнопка «Запустити прогін» виконує справжній `SessionRunner`: три сценарії каналу по п'ять seed через незмінений `channel.py`. Сторінка отримує стан через API і оновлює результати системи. Інші розділи показують дані, розраховані або прочитані під час старту програми; ми не видаємо їх за результат щойно запущеного Runner.
>
> Якщо прогін не вдався або перевищив 90 секунд, попередній успішний результат залишається на екрані, а помилка показується окремо. Результат, який прийшов після тайм-ауту, не замінює збережений. Так ми можемо продовжити демонстрацію навіть за збою каналу.

## Що відкрити

1. Із кореня репозиторію виконати `dotnet run --project tools/Telemetry.Present`. Відкрити адресу, яку надрукує програма; типово це `http://localhost:5050/`.
2. На «Огляді» показати конвеєр. Далі перейти розділами команди; у «Стисненні» показати чотири різні розміри `ref_04` і місткість пакета.
3. У «Системі» натиснути «Запустити прогін», дочекатися позначки «живий прогін» і показати Q та R трьох сценаріїв.
4. Якщо потрібно показати код: `tools/Telemetry.Present/Program.cs`, `DemoData.cs`, `LiveRun.cs`, `Server.cs`, `wwwroot/index.html`.

## Як програма влаштована

| Частина | Роль |
|---|---|
| `Program.cs`, `Preflight.cs` | Запуск, пошук репозиторію, перевірка Python і потрібних файлів. |
| `DemoData.cs` | Дані для окремих розділів із реального коду, `session.csv`, еталонів і збережених експериментів. Рахується під час старту. |
| `Server.cs` | Локальний `HttpListener`; HTML читається з диска на кожний запит. `GET /api/overview` віддає дані розділів, `GET /api/state` — стан Runner, `POST /api/run` — запуск. |
| `LiveRun.cs` | Фоновий `SessionRunner`, запобігання паралельним запускам, тайм-аут 90 с, збереження попередніх даних при збої. |
| `wwwroot/index.html` | Навігація, графіки, таблиці, світла/темна тема, опитування стану прогону. Без сторонніх JS-бібліотек. |

## Короткі відповіді на питання

**Чи всі числа на сторінці живі?** Живий Runner оновлює системні Q/R. Дані перцептрона й ГА походять зі збережених результатів, еталони та вікна сеансу обчислюються при старті. Навчальні приклади підписані окремо.

**Чи кнопка повторно навчає перцептрон або запускає ГА?** Ні. Вона запускає повний сеанс передавання. Повне навчання й оптимізація мають окремі команди та можуть перезаписувати файли результатів.

**Чому `ref_04` має 771 Б, якщо ліміт 512 Б?** Ліміт стосується пакетів нашого передавача. Приймач за специфікацією повинен приймати коректний еталонний пакет будь-якого розміру.

**Що буде при двох натисканнях «Запустити прогін»?** Паралельний запуск відхиляється кодом 409; інтерфейс стежить за вже запущеним прогоном.

**Що буде без Python або при помилці каналу?** Перевірка до старту повідомляє про відсутній Python; збій Runner показує повідомлення й не прибирає останні успішні дані.

**Чому сторінка локальна?** Для захисту потрібен надійний запуск на ноутбуці без мережі та без окремої інфраструктури. Сервер слухає тільки localhost.

## Перевірки перед захистом

```bash
dotnet build -c Release
dotnet format --verify-no-changes
dotnet test -c Release /p:CollectCoverage=true /p:Threshold=80 /p:ThresholdType=line /p:ThresholdStat=total
dotnet run --project tools/Telemetry.Present
```

У перевірці 14 листопада 2026 року: 295 тестів пройшли, загальне покриття рядків 90,88 %. Сторінку перевірено в Chrome на ширинах 390, 768, 1024, 1280 і 1920 px у світлій та темній темах; навігація, перемикач теми і живий Runner працювали без помилок JavaScript.
